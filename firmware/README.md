# Прошивка ESP32

`MediTrack/MediTrack.ino`: Arduino-ESP32 3.x, ArduinoJson 7.x.
Скопіюйте `secrets.example.h` у `secrets.h`, задайте Wi-Fi, адресу API, ID і
секрет пристрою. GPIO18 — сигнал SG90. Завантажуйте для своєї моделі ESP32;
базова ціль перевірки — ESP32 Dev Module (`esp32:esp32:esp32`).

Прошивка використовує LEDC 50 Гц, тайм-аути HTTP 3/5 секунд і повторення
3–60 секунд. Без мережевого часу новий рух не починається. HTTP призначений
для ізольованої демонстраційної мережі; підтримка HTTPS у цьому sketch не реалізована.

NVS містить один запис: UUID події, UUID циклу, позицію, ціль, фазу та результат.
Перед рухом зберігається намір; після витримки — результат. Перезапуск у фазі
руху дає `uncertain`, а повтор confirm не викликає повторного руху. Помилка
запису NVS блокує роботу. Це не замінює датчик положення або падіння таблетки.
Якщо NVS втрачено, а сервер уже видав команду дози, прошивка повідомляє
`uncertain` без руху. Після цього можна виконати /service і повне спорожнення.
Для нових рухів необхідний доступ до NTP; без точного часу прошивка чекає.

Після кожного ввімкнення PWM спочатку вимкнений. Serial Monitor: 115200 бод,
новий рядок. `ALIGN` дозволяє продовження тільки після огляду відповідності
фізичної мітки збереженій позиції. При невизначеному результаті потрібен Home.
`EMPTY` підтверджує, що **всі комірки та канал вручну спорожнені**, і дозволяє
отриману від сервера команду Home. Сам по собі EMPTY не створює команду.

## Калібрування

1. Без доз і без приєднаного диска виконайте серверний /service та локальне EMPTY.
2. Встановіть ріжок так, щоб вікно диска відповідало мітці Home 0°.
3. На порожньому механізмі виміряйте кути 20–160°. Налаштуйте `PULSE_HOME_US`
   та `PULSE_160_US`; 600/2200 мкс — лише початкові припущення. За протилежного
   напряму поміняйте значення місцями. Не допускайте упору та тривалого гудіння.
4. Перевірте всі вісім позицій, відсутність відкриття сусідньої комірки та
   порожнє повернення. Не завантажуйте дози до завершення цих перевірок.

Хостовий тест `test_mechanism.cpp` перевіряє спільні кути та заборону переходу
8→1. Він не емулює Wi-Fi, NVS або електричне керування SG90.

## Відтворення перевірки компіляції

Використано Arduino-ESP32 **3.3.13**, ArduinoJson **7.4.3**, ціль
`esp32:esp32:esp32`. У цьому workspace CLI та залежності містяться в `.tools`:

```powershell
.tools/arduino/arduino-cli.exe compile --config-file .tools/arduino/config.yaml --fqbn esp32:esp32:esp32 --build-path .tools/arduino/build firmware/MediTrack
```

Для іншого комп'ютера встановіть ці версії через Arduino IDE/CLI та створіть
власний `secrets.h`. Перевірка використовує лише шаблон налаштувань; плата
не прошивалася, Wi-Fi і Telegram під час компіляції не викликаються.
